## 4. Bug: ID Tabrakan Setelah Hapus Data

**Laporan user:** "vendor/customer ko gabisa di-create ulang ya setelah dihapus satu?"

**Penyebab:** ID baru dihitung dari `array.length + 1`. Begitu ada data yang dihapus, panjang array berkurang, jadi ID yang "baru" dihitung ulang bentrok dengan ID yang sudah ada.

**Fix:** Ganti ke counter persisten per entity (`vendorSeq`, `customerSeq`, `userSeq`, `roleSeq`, `pvSeq`, dst) yang cuma pernah naik, tidak pernah dihitung ulang dari panjang array. Diterapkan ke Vendor, Customer, User, Role, dan Payment Voucher.

- Sempat gabung PV In/Out jadi 1 menu "Payment Voucher" atas permintaan, lalu **direvert** balik ke struktur semula (PV → PV In / PV Out) atas permintaan user juga.

## 7. Menu Worklist Terpisah: Approval, Payment, Tax

User minta tambahan menu di bawah Finance: **Approval**, **Payment**, **Tax** (dengan **Tax In**/**Tax Out**) sebagai worklist tersendiri — di luar rencana awal yang bilang ini cuma tab. Diimplementasikan sebagai tabel worklist yang filter PV per tahap, linknya tetap membuka tab yang sama di Detail PV.

### Bug 1 — Sidebar tidak reaktif
**Laporan:** klik menu lain, submenu yang tadinya kebuka tidak ikut collapse/expand sesuai halaman aktif.
**Penyebab:** `isOpen` di `SidebarNavItem` cuma dihitung sekali saat mount (`useState(isChildActive)`), tidak update pas navigasi client-side.
**Fix:** tambah `useEffect` yang sync `isOpen` ke `isChildActive` tiap kali berubah.

### Bug 2 — Sidebar highlight salah menu
**Laporan:** buka dari menu "Tax In", tapi Sidebar tetap nge-highlight "PV In".
**Penyebab:** semua halaman detail PV cuma ada di `/finance/pv/pv-in|pv-out/...`, jadi dari worklist manapun (Approval/Payment/Tax) linknya balik ke situ.
**Fix:** bikin route detail khusus per worklist (`/finance/approval/[id]`, `/finance/payment/[id]`, `/finance/tax/tax-in/[id]`, `/finance/tax/tax-out/[id]`), semuanya reuse komponen `PaymentVoucherDetailTabs` yang sama dengan `initialTab` beda-beda. Tabel worklist pakai prop `basePath` (bukan `tab`) buat nentuin link mana yang dipakai.

### Bug 3 — Crash Server/Client Component
Prop `extraFilter` (function) dikirim dari Server Component ke Client Component (`PaymentVoucherWorklistTable`) → error "Functions cannot be passed directly to Client Components". Fix: ganti jadi prop boolean `onlyMissingTaxInvoice`.

**Request:** nominal pajak (PPN/PPh 23/PPh 21) di tab Tax diwarnain merah, dan tab Payment + Tax masing-masing ditambah upload dokumen (bukti pembayaran & bukti pajak).

- Nominal PPN/PPh 23/PPh 21 di ringkasan tab Tax dikasih warna `text-destructive` (merah).
- Tab **Payment**: tambah field **Bukti Pembayaran** (file picker, muncul setelah status `paid`, gated `PV_PAY`), disimpan lewat endpoint baru `PATCH /payment-vouchers/:id/payment-proof`.
- Tab **Tax**: tambah field **Bukti Pajak** di samping input Faktur Pajak, disimpan bareng lewat `PATCH /payment-vouchers/:id/tax-invoice` (sekarang terima `taxInvoiceNumber` + `taxProofFileName` sekaligus).
- Pola upload mengikuti pola "Lampiran" yang sudah ada — cuma menangkap nama file, belum benar-benar upload ke server (masih mock).
- `paymentProofFileName` & `taxProofFileName` ditambahkan ke tipe `PaymentVoucher` dan seluruh data dummy.

### Bug ditemukan saat implementasi: regex tabrakan di mock adapter
Endpoint `PATCH /payment-vouchers/:id/pay` pakai regex tidak di-anchor (`/\/payment-vouchers\/.+\/pay/`), yang ternyata ikut ke-match sama request ke `/payment-proof` (karena `/pay` adalah prefix literal dari `/payment-proof`, dan `axios-mock-adapter` mencocokkan sesuai urutan pendaftaran). **Fix:** semua regex PATCH terkait PV (`submit`, `approve`, `reject`, `pay`, `tax-invoice`, `payment-proof`) di-anchor jadi pola `[^/]+...$` supaya cuma cocok satu segmen ID dan berhenti tepat di akhir path.
